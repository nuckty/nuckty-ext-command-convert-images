# @nuckty/ext-command-convert-images

> **Кодировать изображения контента в AVIF и WebP — команда `convert-images`.**

Командное расширение для [nuckty](https://github.com/nuckty/nuckty). Создаёт варианты WebP и AVIF рядом с PNG/JPEG, понижая качество до достижения целевого размера. Кэш MD5 позволяет пропускать завершённые преобразования. Сборка копирует готовые варианты; sharp нужен только этому расширению. Если варианты и кэш хранятся в репозитории контента, после клонирования их можно использовать повторно. Команда сама не делает коммитов.

## Что добавляет

Одну команду CLI, регистрируемую через `env.commands`:

```
nuckty convert-images [contentDir] [--dry-run] [--force]
```

- `contentDir` — корень для сканирования (по умолчанию текущий каталог).
- `--dry-run` — сообщает, что будет записано, ничего не меняя на диске.
- `--force` — перекодирует даже файлы, уже известные кэшу.

## Как работает

1. Рекурсивно сканирует каталог контента на PNG/JPEG (пропускает `.git`).
2. Пропускает хэш только после завершённого прохода и при наличии записанных в кэше вариантов рядом с этим исходником (если не `--force`). Старые записи без признака завершения безопасно перекодируются один раз.
3. Сначала кодирует WebP из оригинала до меньшего размера. AVIF также кодируется из оригинала; целевой размер — размер созданного WebP, а если WebP не создан — размер оригинала. Если вариант не становится меньше даже при качестве 1, он не сохраняется.
4. Записывает размеры и признак завершения в `convert-images.json` в корне сканирования. При необходимости сохраните этот файл и варианты в репозитории самостоятельно.

Запускайте команду из корня настроенного сайта, передавая каталог контента: `npx @nuckty/core convert-images external/content`.

## Почему отдельный шаг

`nuckty build` копирует готовые варианты в артефакт и не вызывает sharp. Кодирование запускают отдельно при изменении изображений. Как и `content-external`, это явный шаг подготовки входных файлов для сборки.

Некорректный кэш и исходники PNG/JPEG с одинаковым именем выходного файла останавливают команду до любых записей. Исправьте или удалите некорректный кэш либо переименуйте конфликтующий исходник и повторите запуск. Каждый вариант кодируется в уникальный временный файл рядом с результатом и заменяет предыдущий файл только после успеха. Ошибка кодировщика сохраняет прежние файлы и оставляет хэш для повторной обработки; успешно созданный WebP сохраняется при отказе AVIF. Завершённый проход, не давший меньший размер, кэшируется без этого варианта. `--dry-run` не меняет файлы, в том числе при ошибках.
